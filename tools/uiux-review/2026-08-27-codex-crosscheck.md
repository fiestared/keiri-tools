また、Grokの「結果領域64ページすべてにaria-live」は誤りで、少なくとも4ページに更新領域の読み上げ漏れが残っています。表の `scope` 104ページも、狭い定義では正しいものの、部分欠落を含む母集団228ページを表していません。

## 指定6点の再検算

### (a) F1: shell幅二系統

- 再集計: WIDE 384、NARROW 32（非embed・非figcheck416ページ）。Grokの件数は一致。
- 実測: 1280pxでWIDEのヘッダ/h1左端は80px、NARROWは304px。これも一致。
- 判定: **F1としては却下**。二系統の存在は観測事実だが、現行の明示的なページ型設計であり、一貫性バグではない。
- 根拠:
  - `docs/assets/style.css:61-66` は「同じページの左端を1本に揃える」と定義。
  - `docs/assets/style.css:85-95` は一覧・toc等を持たないページの器を672pxに落とし、ヘッダ・本文・フッタをまとめて中央へ寄せる意図を明記。
  - `node tests/test_left_edge.mjs`: 411ページ全件合格。
  - `node tests/test_section_width.mjs`: 411ページ全件合格。
- 誤適用: 「全ページ共通の絶対x座標」という規範は、設計記録にもテストにもない。守るべきなのは同一ページ内の整列と、本文672／一覧1120の役割分担。
- 改善: F1提案どおりヘッダだけ常時1120へ戻すと、NARROWページでヘッダ左80px・本文左304pxとなり、既に解消したページ内分裂を再導入する。実施しない。
- 確信度: 高。

### (b) 旧nav 19本 / footer 15本

- 旧nav: **19本で一致**。397本が現行4項目「ツール／補助金／コラム／資産形成」、19本が旧3項目「ツール一覧／コラム／運営者情報」。代表は `docs/column/36-kyotei/index.html:138`。
- `footer.site` 欠落: **15本で一致**。代表は `docs/shohizei/index.html:405`。
- 判定: navは採択。footerはデザイン・保守性として採択、SC 2.5.8断定は保留。
- 証拠: 15本のフッタリンクは実測12px高・padding 0で、`.site` 付きの `footer.site a { padding:6px 0 }` が当たっていない。ただしWCAG 2.5.8にはinline target例外があり、マークアップの役割を確認せず15本すべてを規格違反とは断定できない。
- 改善: nav生成元へ19本を同期し、15本のfooter classとリンク集合を共通テンプレートへ揃える。
- 確信度: 件数・見た目は高、WCAG違反判定は中以下。

### (c) `.tool-cta` / `.summary-box` は恒久方針違反か

恒久方針 `design/ui-no-left-accent-border-cards` は名称より範囲が広く、本文で次を明記しています。

- 結論・要約は「枠で囲わず」階層化する。
- リンク導線は「カードではなく、上下罫線のリスト行と矢印」にする。

したがって、**リンクである `.tool-cta` と、実際に結論・要約を示す `.summary-box` には方針が適用されます**。ただしクラス名だけで全インスタンスを同じ意味に決めるGrokの母数は広すぎます。

- `.tool-cta`: 352ページ406個。
  - `<a>` は351ページ402個で、リンク導線方針の直接対象。F6はこの範囲で採択。
  - `<button>` は `docs/shohizei/index.html:188,214,253,294` の4個だけ。これはリンク方針ではなく、アクションボタンへリンク用クラスを誤用したF9として直す。
- `.summary-box`: 149ページ200個。
  - 多くは結論・まとめ・冒頭要点で方針対象。
  - 同じクラスが計算式、仕訳例、ダウンロード、送信完了などにも転用されており、149ページ全部を「要約方針違反」とは確定できない。
  - 役割を分類し、真の結論・要約だけ枠を外す。計算例や状態通知は、その役割に合う別コンポーネントへ分離する。
- 判定: F6は**一部採択（402リンクは採択、4ボタンは別問題）**、F7は**一部採択（規範適用は正しいが149ページ一括は誤適用）**。
- 確信度: 適用規範は高、`.summary-box` 個別分類は中。

### (e) `scope` の母数差

ソース中の `<table>...</table>` を、通常HTMLとJavaScriptテンプレート文字列を含めて再走査した結果です。

| 定義 | 全451 | 非 `.nopublish` 442 |
|---|---:|---:|
| 表総数 | 1,815 | 1,779 |
| 表を含むページ | 426 | 420 |
| `th` 総数 | 5,921 | 5,792 |
| `scope` 付き `th` | 4,369 | 4,246 |
| `scope` なし `th` | 1,552 | 1,546 |
| 一部でも `scope` なし `th` を含む表 | 627 | 621 |
| 同ページ数 | 228 | 225 |
| ページ内に `scope=` が1件もない表ページ | 104 | 104 |

Grokの104は「表があり、そのページのソースに `scope=` が一つもない」という狭い集計で、数値自体は再現しました。しかし、同じページ内で一部の表・見出しだけ対応済みのケースを落とします。残件レビューの母集団は「一部でもunscoped `th` がある」228ページ（公開225ページ）が上限です。

Codex独立レビューの225ページは「全件WCAG違反」ではなく、意味上の分類が必要な候補集合として提示しています。Grokの104も全件をデータ表と目視確認していないため、どちらもそのまま違反件数にはできません。代表 `docs/column/dattai-ichijikin/index.html:317-323` では、列見出しにscopeがなく行見出し相当セルも`td`であることを個別確認済みです。

判定: F13は**一部採択**。改善方向は正しいが、104を全残件と呼ぶと過少集計。

### (f) 375px / 390pxの横スクロール差

Grokが使ったPlaywright `browser.newContext({viewport:{width:375}})` は、`window.innerWidth=375`になる正しい方法です。ここは既存 `tests/test_no_hscroll.mjs` の直接 `--window-size=375`（実際は500px）より信頼できます。

同じPlaywright方式で全451ページを375pxと390pxで再走査しました。

| ページ | 375px | 390px | 原因 |
|---|---:|---:|---|
| `/embed/` | `scrollWidth=394`、+19px | `scrollWidth=394`、+4px | `.row` のgrid itemがiframeのmin-content幅に押される。`min-width:0`がない |
| `/column/furikomi-furikae-chigai/` | `scrollWidth=477`、+102px | `scrollWidth=477`、+87px | `pre > code` の長い仕訳2行。共有CSSに`pre`の横スクロール処理がない |
| その他449ページ | 0 | 0 | 今回のロード時DOMで確認 |

よって、Grokの `/embed/` +19pxは採択。ただし「代表ページではembedだけ」という範囲に限る結果で、サイト全数結論に伸ばせません。GrokもCodex独立レビューも `/column/furikomi-furikae-chigai/` を代表抽出で漏らしました。375と390の差は、問題の有無ではなく超過量（+19→+4、+102→+87）です。

## Grokだけが拾った、採用すべき発見

1. **旧nav 19本**: 現行4項目への同期漏れ。低コストで信頼・回遊を改善できる。
2. **`footer.site` 欠落15本**: 共通スタイルとリンク集合から外れている。アクセシビリティ断定とは分けて修正候補にする。
3. **embed案内の27/31矛盾**: `docs/embed/index.html:46` と `:83`。業務サイトの信頼を直接損なうため優先度が高い。
4. **FAQマークアップ逸脱2本**: `column/shokibo-kyosai-uketori:376`、`column/kokuho-hokenryo:432`。`h3+p`型へ戻す。
5. **`shohizei` のリンク用CTAクラスをbuttonへ誤用**: 4個。`button.primary`へ揃えるのが妥当。
6. **embedカタログの実375px overflow**: Playwright手法は正しく、+19pxを再現。390pxでも+4px残る。
7. **結果コピー欠落2本**: 規格違反ではないが、既存ツール慣行からの型漏れとして有効。

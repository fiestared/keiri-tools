## 3. 評価軸ごとの所見

### 3.1 視覚的一貫性

本体（共有 `style.css`）は、色・本文16px・下罫線見出し・リスト行一覧までは一本化されている。壊れているのは **シェル幅・ヘッダ中身・フッタ印・埋め込み**。

トップと `/about/` を1280で並べると、ブランドの左端が **80px と 304px** に跳ぶ。同じヘッダ部品なのに、toc の有無で `--shell` が切り替わるため。

### 3.2 レイアウト／幅／余白／階層

記事は「本文672＋右toc236」が成立している（toc `left:800px`, `top:84px` を実測）。これは意図どおりで、本文を1120に伸ばすべきではない。

問題は **ツール型が toc の有無で二分割**されること。`/tedori/` は左80の業務フォーム、`/eigyobi/` `/shohizei/` は画面中央の672アイランド。階層（h1 24px vs `.hero h1` 27px）も型で割れている。

コラム一覧の `.post-list .p-desc` だけ **3行クランプが残っている**（ツールカードからは2026-08-24に外した）。

### 3.3 業務サイトとしての信頼感

強い。代表記事（貸倒損失）は条文の語尾差・出典・「確認範囲を超えるので断定しない」まで書いてあり、YMYLとしてむしろ反AI。`/nenshu/` の全区分表、`/about/` の一次情報と自動テストの説明は信頼の核。

弱いのは **埋め込みの別ブランド**（`keiri-tools` 小文字＋🧮＋ティール）と、資格免責を inline 12px でフッターにベタ貼りしている層（`.trust` は CSS 未定義、53ページが `style=` 直書き）。

### 3.4 AIっぽさ

絵文字スパム・汎用グラデ・「徹底解説」「今すぐチェック」はほぼ無い（`linear-gradient` 0、`いかがでしたか` 0、`わかりやすく解説` 0）。

残っているAI顔は次:

- **型の反復**: コラム337が同じ骨格（breadcrumb → 結論リード → toc → 図 → まとめ箱 → 緑CTA → FAQ → 出典）
- **同一フレーズ**: 「結論から言うと」**309/337**
- **塗りつぶしCTA**: `.tool-cta` が **352ページ・406個**
- **要約の緑囲み**: `.summary-box` **149ページ**（うちコラム130）
- **注意ボックス過多**: `.callout` 合計1907、**4個以上が261ページ**（最多は `hoteichosho-goukeihyo` の17）
- **埋め込み**: 番号付きステップ、ダークコードブロック、カードグリッド、`🧮` **32/32**
- FAQの中身は **設問2438種のうち重複≥5が0、≥2が4**。テンプレ反復なのは枠であり、中身を削る理由にならない

### 3.5 ページ型ごとの例外

- **コラム**: FAQ・出典・結論ファーストは仕様。消さない。
- **ツール**: カード1枚＋全幅 `button.primary` が正規。`shohizei` の6カード＋`button.tool-cta`（幅shrink）は逸脱。
- **補助金**: 絞り込みのチップグリッドは探索UIであり、トップのリンクカード禁止とは別物。
- **embed**: 他サイトのiframe前提なのでヘッダ無しは正しい。ただし色・フォント・絵文字まで別製品になっているのは過剰。
- **figcheck / nopublish**: 索引から外してもURLは生きる。デザイン監査の優先度は下げてよい。

### 3.6 アクセシビリティ

本体のAA層（コントラスト宣言、skip-link、aria-live、フォーカスリング、印刷、Windowsフォント、タブAPG）は健全。残るのは **局所**:

- SVG文字に装飾色 `--warn-line`（白上 ~1.57:1）が7箇所
- `footer` 非 `.site` 15本のリンク行高
- 表 `scope` 欠落104ページ
- embed入力枠が再び薄い
- embedカタログ375pxでページ幅+19px
- ラジオチップ未選択枠は `--line`（1.28:1）だが、ネイティブ radio があるので **SC 1.4.11 の確定違反とは言わない**

## 4. 指摘（各件: 重大度・件数・場所・事実・改善・確信度）

### F1. 1280pxでヘッダ左端が80pxと304pxに割れる

- **重大度**: 高（一貫性。規格違反ではない）
- **該当**: NARROW **32** / WIDE **384**（非embed・非figcheck）
- **代表**: 広=`docs/index.html`（h1x=80）、狭=`docs/about/index.html`・`docs/eigyobi/index.html`・`docs/shohizei/index.html`・`docs/hojokin/index.html`（h1x=304）
- **セレクタ/行**: `docs/assets/style.css:92-96`
  `body:not(:has(main nav.toc)):not(:has(main .tcat))… { --shell: 672px; }`
  と `header.site` の `padding: … calc((100% - var(--shell)) / 2)`
- **観測**: Playwright 1280。`--shell` を落とすとヘッダ中身も中央へ寄る。トップ→営業日でブランドが224px跳ぶ。
- **改善**: ヘッダ／フッタのシェルは常に1120のまま、**本文列だけ**672にする。`--shell` をページ型で変えない。左端を1本にする、というコメント（style.css:61-65）と今の実装が矛盾している。
- **確信度**: 高（実測座標）

### F2. 埋め込み32ページが別デザインシステム

## 6. AIっぽさが強いページ型ランキング

強い順。**中身の正確さではなく、見た目の生成感**。

| 順 | 型 | なぜ |
|---|---|---|
| 1 | 埋め込みカタログ＋ウィジェット（32） | 別パレット、絵文字、番号ステップ、カードグリッド、種数の食い違い |
| 2 | コラム記事の**クロム**（337） | 緑CTA・まとめ箱・FAQ・「結論から言うと」。本文はむしろ反AI |
| 3 | 多カード計算機（`shohizei` ほか） | 同じ白カードが段々 |
| 4 | article付きツール（35） | 計算機の下に記事型FAQ・出典・CTAがフルセット |
| 5 | 補助金検索（3） | チップ過多。ただし探索には必要 |
| 6 | トップ | リスト化後はかなり業務的。残るのはQA箱と「✓ 無料」バッジ |
| 7 | 単機能ツール（`eigyobi` 等） | 入力→結果→短いFAQで、AI感は薄い |
| 8 | about / policy | 資格の自己申告が具体で、テンプレに見えない |
| 9 | `nenshu` 型の表ページ | 数字の密度が「生成文」を殺している＝このサイトの強み |
